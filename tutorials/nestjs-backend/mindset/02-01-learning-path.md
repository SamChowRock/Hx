# 2. 前端研发转后端：学习目标与核心思维

> [返回教程首页](../README.md) · [本模块目录](README.md)

## 2.1 学完后应当会什么

完成本教程后，你应该能够：

1. 启动并调试 API、Worker 和基础设施；
2. 解释 Module、Controller、Provider 和依赖注入的关系；
3. 从路由一路跟踪到校验、认证、授权、数据库事务和响应；
4. 修改 Prisma Schema、生成 Migration 并使用 Prisma Client；
5. 独立新增一个符合本项目约定的业务模块；
6. 正确处理租户隔离、角色权限、CSRF 和审计日志；
7. 把非即时副作用交给 Outbox + Worker；
8. 编写单元测试和真实数据库 E2E 测试；
9. 完成类型检查、测试、构建与容器验证；
10. 判断什么时候需要 Redis、队列或微服务，而不是为了“技术先进”盲目引入。

## 2.2 推荐的四阶段学习法

| 阶段                 |  建议时长 | 目标                              | 对应章节       |
| -------------------- | --------: | --------------------------------- | -------------- |

## 2.3 如果你是后端初学者，先补齐这些最小知识

你不需要先学完整本计算机网络或数据库教材，但应能解释下面这些概念。

### TypeScript 只需要额外记住一件事

你已经熟悉 JS/TS，本教程不再解释语法。后端边界上最重要的区别是：**TypeScript 类型在运行时已经消失，网络、数据库 JSON 和外部 Provider 数据都不因类型标注而可信。**

```ts
const body = request.body as CreateProjectInput; // 只有类型断言，不安全
const body = createProjectSchema.parse(request.body); // 运行时真正校验
```

另外，Node.js 擅长大量异步 I/O，不代表 CPU 工作免费。Argon2、压缩、图片处理和大 JSON 计算会占用 CPU/线程池，因此本项目限制密码计算并发，重型文件处理应交给受控 Worker。

### HTTP 最小知识

一个 HTTP 请求由 Method、URL、Header、Cookie 和可选 Body 组成：

```http
POST /api/organizations/xxx/projects HTTP/1.1
Host: localhost:3000
Content-Type: application/json
Cookie: dev-session=opaque-secret
Origin: http://localhost:5173
X-CSRF-Token: token

{"name":"Learn NestJS"}
```

常用 Method 语义：

| Method | 典型语义           | 是否通常修改状态 |
| ------ | ------------------ | ---------------- |
| GET    | 获取资源           | 否               |
| POST   | 创建资源或执行命令 | 是               |
| PUT    | 整体替换资源       | 是               |
| PATCH  | 部分修改资源       | 是               |
| DELETE | 删除资源           | 是               |

常用状态码：

| 状态码 | 本项目中的含义                    |
| ------ | --------------------------------- |
| 200    | 查询或显式设为 OK 的操作成功      |
| 201    | Nest 默认的 POST 创建成功         |
| 202    | 请求已接受，后续可能异步处理      |
| 204    | 成功但没有响应体                  |
| 400    | Zod 校验失败等非法输入            |
| 401    | 没有有效身份                      |
| 403    | 有身份，但 Origin/CSRF/角色不允许 |
| 404    | 授权范围内找不到资源              |
| 409    | 唯一约束、一次性 Token 或版本冲突 |
| 429    | 触发限流                          |
| 500    | 未预料的服务端错误                |
| 503    | 依赖未就绪或功能未配置            |

401 和 403 很容易混淆：**401 是“你是谁还没证明”，403 是“知道你是谁，但仍不允许”。**

### SQL/关系数据库最小知识

- Table 是记录集合，Row 是一条记录；
- Primary Key 唯一标识 Row；
- Foreign Key 保证引用目标存在；
- Unique Constraint 防止重复事实；
- Index 用额外空间换查询速度；
- Transaction 保证一组操作原子提交或全部回滚；
- `WHERE` 决定查询范围，多租户系统漏掉 `organization_id` 可能成为安全漏洞；
- Migration 是数据库结构的版本历史。

Prisma 不是数据库本身。它把 TypeScript 调用转换为 SQL，但你仍需要理解关系、约束、索引和事务。

## 2.4 如何真正使用这份教程

建议不要只阅读。为学习建立一个临时分支：

```bash
git switch -c codex/learn-nestjs-backend
```

每章按“读、画、改、测”四步执行：

1. **读**：打开章节提到的真实文件；
2. **画**：用自己的话画出请求或数据流；
3. **改**：完成一个很小的变更，例如给校验增加最大长度；
4. **测**：先预测结果，再运行测试验证。

为每个练习保留三个证据：

- 一次成功请求及响应；
- 一次被安全拒绝的请求及响应；
- 一条最终数据库记录或测试断言。

只会让接口返回 200，不代表学会后端。你还需要证明非法输入、低权限角色、跨租户 ID、重复请求和依赖失败时系统行为正确。
